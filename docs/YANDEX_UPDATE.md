# Как обновлять приложение в Yandex Cloud

Гайд для владельца: что делать, когда проект уже развёрнут по [YANDEX_DEPLOY.md](YANDEX_DEPLOY.md) и вы изменили код, настройки или тексты. Справочники: [DEPLOYMENT.md](DEPLOYMENT.md), [YANDEX_CLOUD.md](YANDEX_CLOUD.md). Команды для PowerShell на Windows, из корня репозитория.

## Что запускать в зависимости от того, что вы изменили

| Что изменилось | Что делать |
| --- | --- |
| Код приложения, сайта, бэкенда, тексты экранов | Раздел «Обычное обновление»: коммит, `git push`, `release` |
| Схема базы (миграции Prisma) | То же: `release` сам применяет миграции |
| Настройки инфраструктуры в `terraform.tfvars` (размер базы, лимиты, адреса) | Раздел «Изменение настроек»: `infra:apply`, затем `release` |
| Пароли базы или JWT-секрет | Не меняйте сами: [процедура ротации](YANDEX_CLOUD.md#database-password-rotation) |
| Новая хостес, новый администратор | Релиз не нужен: роль выдаётся на `/admin/users` |
| Баллы станций и состав станций у **уже запущенного** мероприятия | Релиз не поможет: первое мероприятие создаётся один раз, QR-коды уже напечатаны. Меняется только миграцией или SQL вместе с разработчиком |

## 1. Подготовка окна PowerShell (каждый раз)

Переменные окружения не сохраняются между окнами. В каждом новом окне:

```powershell
cd "D:\Projects\Event Station Tracker YandexCloud"
. .\scripts\deploy-env.ps1
```

- Скрипт подключает пути к программам, настройки Terraform, секреты (`C:\Users\<вы>\.etsys\secrets.ps1`) и токен Yandex Cloud (он живёт 12 часов: при ошибке `Unauthenticated` выполните строку ещё раз).
- Секреты в `secrets.ps1` (три пароля базы и JWT) **должны быть теми же, что при первом деплое.** Нельзя пересоздавать файл и менять значения. Копия должна лежать в менеджере паролей.
- **VPN выключен**, Docker Desktop запущен.
- Ключ `-WithAdmin` **не используйте**: администратор создаётся только первым релизом, новое значение сбросит пароль администратора.

## 2. Обычное обновление (код, тексты, миграции)

1. **Проверьте локально**, что всё собирается и тесты проходят:

```powershell
bun run typecheck
bun run lint
bun run test:webapp
bun run test:backend:unit
```

   Для больших изменений (база, регистрация, начисление баллов) добавьте `bun run test:backend:integration` и `bun run e2e:webapp` (нужен Docker).

2. **Закоммитьте и отправьте на GitHub.** Релиз собирается из запушенной ветки `main` и требует чистого дерева:

```bash
git add -A
git commit -m "Что изменили"
git push
git status
```

   `git status` должен сказать «nothing to commit, working tree clean» и «up to date with origin/main».

3. **Пробный прогон** (ничего не меняет в облаке):

```powershell
bun run release -- yandex --dry-run
```

   Прочитайте план. Если он предлагает **удалить или заменить** ресурс, остановитесь: скрипт без явного разрешения такое не сделает, и вам нужен разработчик.

4. **Релиз:**

```powershell
bun run release -- yandex
```

   Он по порядку: собирает образ из закоммиченного кода, загружает его в реестр, запускает миграции базы (если миграция упала, релиз останавливается, а прежняя версия продолжает работать), переключает API и задачи на новую версию, выкладывает сайты, проверяет адреса. Обычно 10-20 минут.

5. **Проверьте результат:**
   - `https://api.<ваш домен>/health/ready` отвечает 200;
   - приложение открывается, вход работает;
   - пройдите один сценарий, который вы изменили.

6. Если релиз остановился на выкладке сайтов: новый бэкенд уже работает, а сайты ещё старые. Просто **повторите** `bun run release -- yandex`: команды безопасно повторять.

## 3. Изменение настроек инфраструктуры

Для размера базы, лимитов запросов, переменных окружения и тому подобного:

1. Измените `infra/yandex/production/terraform.tfvars` (он не в git). Примеры:
   - `postgres_resource_preset`, `postgres_disk_size_gb`: размер базы;
   - `extra_runtime_env = { EVENT_RATE_LIMIT_MAX = "20000" }`: лимит запросов с одного адреса.
2. Посмотрите план и примените основу:

```powershell
bun run infra:plan -- yandex
bun run infra:apply -- yandex --dry-run
bun run infra:apply -- yandex
```

3. Затем выполните `bun run release -- yandex`: релиз применяет новые настройки к контейнерам.

**Правило:** `release` отказывается работать, пока основа не применена. Если он пишет, что основа изменилась или нужен `infra:apply`, сначала выполните `infra:apply`.

**Размер базы можно увеличить, уменьшить диск нельзя.** Диск сам растёт до `postgres_disk_limit_gb`. Смена класса хоста перезапускает базу, делайте это не во время мероприятия.

## 4. Откат

1. Верните код новым коммитом: `git revert <хеш коммита>` (хеш видно в `git log`), затем `git push`.
2. Выполните `bun run release -- yandex`.

Миграции базы идут только вперёд и не откатываются. Поэтому изменения схемы делайте в два этапа: сначала добавьте столбец или таблицу так, чтобы старый код продолжал работать, и только в следующем релизе удаляйте старое. Откат образа без отката кода делать нельзя.

## 5. Если что-то пошло не так

- **Команда упала с ошибкой:** прочитайте последние строки. Почти все шаги безопасно повторять.
- **Логи API и задач:**

```powershell
yc logging read --folder-id b1g673v2mou0tr08qbs5 --group-name event-tracking-system-prod-containers --since 30m
```

- **Релиз пишет про блокировку (lease):** другой запуск ещё идёт или предыдущий оборвался. Убедитесь, что `bun` и `terraform` нигде не запущены, затем следуйте разделу «Lease» в [infra/README.md](../infra/README.md). Принудительно блокировку снимайте только когда уверены, что процессов нет.
- **Provider или зеркало:** `Failed to install provider`, `dial tcp ... terraform-mirror.yandexcloud.net`. Зеркало Yandex нестабильно, повторите команду через минуту.
- **Рабочее дерево не чистое:** `git status`, закоммитьте или отмените лишнее. В частности `terraform init` может дописать хеш в `.terraform.lock.hcl`: такой файл тоже нужно закоммитить.
- **Токен просрочен:** `$env:YC_TOKEN = (yc iam create-token)`.

## 6. Правила для времени мероприятия

- За неделю до мероприятия заморозьте изменения, сделайте репетицию ([YANDEX_DEPLOY.md](YANDEX_DEPLOY.md), раздел «Репетиция»).
- Во время мероприятия выкатывайте только срочные исправления, по одному, и сразу проверяйте регистрацию и сканирование.
- Не меняйте класс хоста базы и не трогайте пароли в эти дни.
- Создавать хостес и назначать администраторов можно в любой момент: это не релиз.

## 7. Важный срок: закрытие Container Registry

Образы лежат в Yandex Container Registry. По [странице закрытия](https://yandex.cloud/ru/docs/container-registry/sunset): с 10 ноября 2026 реестр только для чтения, то есть выпустить обновление будет **нельзя**, а 14 декабря он полностью остановится. До 10 ноября выполните миграцию каталога на Yandex Cloud Registry по [руководству](https://yandex.cloud/ru/docs/container-registry/tutorials/container-registry-migration) (адреса `cr.yandex/...` при этом сохраняются) и после неё сделайте тестовый релиз. Как Terraform проекта поведёт себя с перенесённым реестром, проверено не было: сделайте это заранее, не накануне мероприятия.

## 8. Что должно храниться у вас

- `C:\Users\dmalt\.etsys\secrets.ps1` (пароли и JWT) и копия в менеджере паролей;
- `infra/yandex/.env.terraform-state` (ключ к состоянию Terraform), копия в менеджере паролей;
- файлы `terraform.tfvars` в `infra/yandex/bootstrap` и `infra/yandex/production`;
- пароль администратора.

Если потеряны и секреты, и ключ к состоянию, управлять инфраструктурой этим проектом больше не получится без восстановления ([DEPLOYMENT.md](DEPLOYMENT.md), раздел «Lost state access»).
